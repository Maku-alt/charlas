# Design

## Firma de Charlas

Una charla de este repositorio se reconoce por cuatro rasgos: tesis fuerte, evidencia visible, navegacion silenciosa y cierre editorial memorable. La firma no depende de una paleta, tipografia, barra o plantilla fija.

## Libertad visual

Cada charla debe tener una direccion visual propia. Impeccable puede decidir paleta, tipografia, densidad, composicion, imagen, movimiento y metafora segun la tesis, la audiencia y el contexto de presentacion.

Antes de construir, el Experience Designer Builder explicita de forma compacta:

- concepto rector y tension visual;
- tipo de evidencia dominante;
- tratamiento de imagenes y datos;
- gesto o momento memorable;
- logica de apertura y cierre;
- recursos visuales que evitara.

Esta direccion forma parte de la entrega del Build cuando aporta valor; no requiere un documento ceremonial separado.

## Gramatica editorial

- La apertura instala una tension o pregunta real; no es una portada administrativa.
- Los titulos sostienen una idea, no nombran un tema.
- Cada momento tiene un trabajo narrativo y una prueba visible.
- La secuencia revela, compara, demuestra o hace experimentar; no acumula informacion.
- El speech y la superficie visual se complementan, no se duplican.
- El cierre presenta una sola idea o mensaje y una imagen protagonista relacionada con la tesis.
- Una cita breve y verificada puede elevar el cierre, pero nunca se fuerza.

## Momentos frontend

La unidad de diseno es el momento. Puede adoptar la forma que mejor explique la idea:

- escena editorial;
- evidencia o visualizacion de datos;
- comparacion o transformacion;
- simulacion o exploracion controlada;
- demo o codigo guiado;
- revelacion secuencial;
- cierre visual.

La interaccion debe cambiar lo que la audiencia comprende. Si un gesto no aporta una observacion, decision o revelacion, se elimina.

No existe una cantidad predeterminada de momentos. La experiencia debe ser tan breve como permita la tesis y tan extensa como exija la comprension dentro del tiempo disponible. Si aparecen varios arcos principales, divide el tema en una serie en lugar de comprimirlo.

## Comportamiento compartido

- Presentacion por momentos, sin scroll como ruta principal.
- Navegacion lineal y acceso directo consistentes.
- Controles visibles sin competir con el contenido.
- Fullscreen, limites correctos y estado actual comprensible.
- Interacciones operables por teclado, reiniciables y predecibles.
- Movimiento con proposito y alternativa para reduced motion.
- Stage 16:9 como default util, no como restriccion absoluta para una experiencia que necesite el viewport completo.

## Criterios de calidad

Evita dashboards SaaS, mosaicos de tarjetas repetidas, iconografia tecnologica generica, texto que sustituya evidencia, movimiento decorativo y la misma metafora visual entre charlas.

Usa imagenes con proporcion correcta, foco intencional y procedencia registrada. Cuando se genere una imagen, usa la skill o herramienta real y no placeholders. No incrustes texto dentro de imagenes salvo que la idea lo exija y siga siendo accesible.

Review inspecciona cada momento a tamano real. Un contact sheet o un build exitoso no demuestran calidad visual, interaccion correcta ni legibilidad en proyector.
