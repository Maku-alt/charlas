# Review Spec

## Artefacto a revisar

- `Knowledge-Repo-01-Cuando-Documentar-Tablas-se-Vuelve-Arquitectura-de-Conocimiento.pptx`
- `review/renders/` con renders individuales completos
- `review/contact-sheet.png`
- `review/extracted-text.txt`
- `review/build-report.md`

## Criterios especificos

- La tesis debe leerse como paso de archivos sueltos a memoria comun gobernada, no como venta de herramienta.
- Markdown debe aparecer como punto de partida correcto, no como tecnologia descartada.
- La wiki debe verse util para discovery humano, pero insuficiente como memoria operacional por si sola.
- El knowledge repo debe aparecer como capa gobernada con contrato, ownership, relaciones y proceso de cambio.
- OKF debe tratarse como referencia emergente de formato portable, no como estandar corporativo maduro.
- MCP/API debe leerse como interfaz de consulta para agentes, no como sustituto de la memoria.
- Los catalogs deben usarse como evidencia de metadata relacional, no como benchmark competitivo.
- El cierre debe sostener el mensaje: `La documentacion que escala no guarda paginas: conserva decisiones reutilizables.`
- No debe haber mojibake, caracteres sustituidos, texto cortado ni solapamientos.
- La imagen final debe reforzar una memoria comun viva y no competir con la cita o el mensaje.

## Gates obligatorios

- Confirmar 9 slides.
- Confirmar que el PPTX valida y abre.
- Confirmar render completo de todas las slides.
- Confirmar render nativo de PowerPoint si esta disponible; si no, registrar riesgo residual.
- Revisar contact sheet para ritmo global.
- Inspeccionar slides 5, 7 y 9 con especial cuidado por densidad conceptual y cierre editorial.
- Verificar texto extraido para tildes, signos de apertura y caracteres especiales.

## Decision esperada

- `aprobado` si no hay P1/P2.
- `requiere cambios` si hay mojibake, overflow, imagen final floja o rota, fuente ausente o solapamientos visibles.
