# Estilo comun de las charlas

Este documento captura el estilo compartido de las charlas del repositorio para que futuras presentaciones mantengan una identidad coherente.

## Direccion general

Las charlas deben sentirse:

- tecnicas, pero no academicas
- ejecutivas, pero no corporativas frias
- editoriales, pero no recargadas

La idea no es hacer slides decorativos. La idea es hacer slides con una tesis clara, una prueba visible y una conclusion accionable.

## Sistema visual

### Paleta

- fondo claro principal: `#F4F0E8`
- tinta principal: `#0F172A`
- texto secundario: `#475569`
- azul profundo: `#102A43`
- azul secundario: `#16324F`
- acento naranja: `#C75C2A`
- acento naranja claro: `#E07A3F`
- acento verde: `#2D6A4F`
- rojo de tension o riesgo: `#B42318`
- blanco calido: `#FFFDF8`
- arena suave para cierres y barras: `#EADBC8`

### Tipografia

- titulos: display serif o equivalente de alto contraste
- cuerpo: sans limpia y legible
- etiquetas, kickers y microscopias: mono o sans compacta

### Composicion

- slides de fondo claro con una barra superior corta como firma visual
- covers o slides de cierre pueden usar fondo azul profundo
- mucho aire, pocas cajas, jerarquia fuerte
- paneles blancos o marfil con borde suave para comparaciones y tablas
- mensajes de cierre en franjas oscuras o bandas de contraste alto

## Gramatica narrativa

Cada slide debe tener:

- kicker corto
- titulo-conclusion, no tema generico
- objeto de prueba visible
- takeaway claro

### Titulos correctos

- `La mejor decision por defecto es modernizar el stack manteniendo Python 3.10`
- `Los LLMs reabren una pregunta que la nube parecia haber cerrado`

### Titulos incorrectos

- `Versiones de librerias`
- `Cloud vs on-premise`

## Slides frecuentes

Las familias de slide mas usadas en este repo son:

- cover con tesis lateral
- comparacion en paneles
- tabla ejecutiva con lectura
- cards de criterio o decision
- slide de tradeoff
- cierre editorial con cita

## Tono de copy

- espanol claro
- tecnico, pero explicado
- sin hype gratuito
- afirmaciones fuertes solo si tienen respaldo
- si hay incertidumbre, se enuncia como hipotesis o condicion

## Reglas para evidencia

- citar fechas cuando la noticia sea reciente
- diferenciar hechos verificados de rumores
- no usar nombres de empresas si no hay fuente firme
- cuando una slide use mercado, combinar al menos un caso extremo con un caso corporativo conocido

## Cierre editorial

Toda charla debe cerrar con:

- una conclusion estrategica de una linea
- una cita breve, real y atribuida a un referente del dominio
- una imagen editorial protagonista que converse con la tesis

Solo si no se encuentra una cita adecuada tras revisar fuentes y referentes, usa un claim propio como ultimo recurso, sin llamarlo cita ni atribuirlo.

### Reglas de la imagen final

La imagen final:

- debe ser el elemento principal, idealmente full-bleed o casi full-bleed, aunque quede transparentada o parcialmente cubierta por texto
- debe ser una sola escena fuerte, no una slide tecnica escondida dentro de una imagen
- debe evitar tablas, dashboards, bullets, diagramas, iconografia repetida y metaforas genericas
- debe amplificar la tesis con una metafora visual clara y memorable
- debe dejar una zona de lectura limpia para un mensaje breve y la atribucion de la cita

### Diferenciacion entre charlas

Las charlas pueden compartir familia visual, pero no deben cerrar con la misma emocion o la misma metafora.

Ejemplos:

- `Harness Engineer`: energia, motor, combustion, sistema
- `Evolucion Stack Clasico DS`: modernizacion, transicion, refinamiento, upgrade deliberado
- `El Eterno Retorno`: costo, control, infraestructura, tension entre elasticidad y propiedad

La regla es:

- mismo universo editorial
- distinta metafora de cierre
- distinta emocion final
